# Окружение стендов: nginx на одном порту

Снаружи машины или контейнера обычно доступно мало портов. На одном из них (`listen_port` в
`conf/settings.json`) работает nginx. Он раздаёт любое число стендов, каждый под своим путём
`/<имя>/`. Стенды слушают любые внутренние порты из `stand_port_range`. Порты из `direct_ports`
оставлены для прямого доступа без прокси.

| Что | Адрес |
|---|---|
| Панель со списком стендов | `$PROXY_URL/_env/` |
| Стенд `<имя>` | `$PROXY_URL/<имя>/` |
| Стенд с landing | `$PROXY_URL/<имя><landing>` |

`$PROXY_URL` — внешний адрес прокси из `env.yaml` → `proxy.url`. Если внешний порт меняется
(например, после пересоздания контейнера) — поправь `env.yaml`.

Правила для агентов: `rules/stands-proxy.md`. Папка с работающей копией — `env.yaml` → `proxy.dir`
(ниже `$PROXY_DIR`); это может быть и эта папка, и папка другой копии ai-workflow.

---

## Состав

```
nginx-env/
  bin/envctl              утилита управления (Python 3, без зависимостей)
  conf/settings.json      порт nginx (listen_port), диапазон портов стендов (stand_port_range),
                          порт сервиса команд (control_port), прямые порты (direct_ports),
                          wrapper_markers (обёртки процессов стенда, которые останавливаются вместе с ним),
                          reserved_names (запрещённые имена стендов), protected_markers (процессы, которые
                          панель не останавливает). Последние три — под конкретное приложение
  conf/nginx.conf.tmpl    шаблон конфига nginx
  conf/proxy_headers.conf заголовки проксирования (Host, X-Forwarded-*, WebSocket)
  panel/index.html        панель
  stands.d/<имя>.json     реестр: один файл на стенд
  var/                    генерируется: бинарь nginx, конфиг, pid, логи. Руками не править
```

Единственный источник списка стендов — `stands.d/`. Из него `envctl` генерирует
`var/routes.conf` (маршруты nginx) и `var/stands.json` (данные панели).

## Команды

Все команды — из `$PROXY_DIR`:

| Команда | Что делает |
|---|---|
| `bin/envctl up` | Запускает nginx и сервис команд панели. При первом запуске скачивает пакет nginx из Debian в `var/nginx` (без установки в систему). Если работает только nginx — дозапускает сервис команд. |
| `bin/envctl down` | Останавливает nginx и сервис команд панели. Стенды не трогает. |
| `bin/envctl status` | Состояние nginx, сервиса команд и всех стендов. |
| `bin/envctl stop <имя> [--rm]` | Останавливает процесс стенда (см. «Остановка из панели»). С `--rm` — затем удаляет из реестра. |
| `bin/envctl free-port` | Первый свободный порт из `stand_port_range`. |
| `bin/envctl add <имя> --port <порт> [опции]` | Регистрирует стенд или обновляет его запись. Применяет конфиг сразу. |
| `bin/envctl rm <имя>` | Убирает стенд из реестра. Процесс стенда не останавливает. |
| `bin/envctl reload` | Перегенерирует конфиг из `stands.d/` и перечитывает nginx. |

Опции `add`:

| Опция | Назначение |
|---|---|
| `--task` | Задача в виде `<ws>/<задача>`. Показывается в панели. |
| `--title`, `--desc` | Заголовок и описание карточки: ветка, что поднято, особенности. |
| `--session` | ID сессии агента. Защищает запись от перезаписи другой сессией. |
| `--kind` | Тип: `app`, `dev-server`, `backend` и т. п. |
| `--landing` | Путь после префикса, на который ведёт ссылка в панели (`ws.yaml` → `stands.landing`). |
| `--no-strip` | Не срезать префикс: приложение само работает под `/<имя>/`. |
| `--no-start` | Не запускать nginx, если он остановлен. |
| `--force` | Перезаписать стенд, зарегистрированный другой сессией. |

Перед применением `envctl` проверяет конфиг (`nginx -t`). При ошибке прежний конфиг
восстанавливается, nginx продолжает работать.

После перезапуска контейнера nginx сам не поднимается: выполни `bin/envctl up`.

## Как добавить стенд

1. Возьми свободный порт: `bin/envctl free-port`.
2. Подними стенд на этом порту. Слушать можно на `127.0.0.1` или `0.0.0.0`.
3. Зарегистрируй:

   ```bash
   bin/envctl add my-task --port 10100 --task my-ws/MY-1 --kind app --landing /app/ \
     --desc "ветка MY-1, что поднято" --session <ID сессии>
   ```

4. Проверь: `bin/envctl status` и `curl -sI localhost:<listen_port>/my-task/app/`.
5. Когда стенд больше не нужен: останови его и выполни `bin/envctl rm my-task`.

Имя стенда — латиница в нижнем регистре, цифры и `-`, до 40 символов.

### Приложение за префиксом

Большинство приложений работает под `/<имя>/`, если строит адреса запросов относительно адреса
страницы. Как поднимать конкретное приложение (команда запуска, порт в конфиге, dev-сервер) —
в правилах пространства.

Dev-серверы с горячей перезагрузкой часто открывают WebSocket по корневому пути — через префикс
он не пройдёт. Запускай без горячей перезагрузки или используй `--no-strip`.

### Приложение, которое само работает под префиксом

Если у приложения есть настройка базового пути (`BASE_PATH`, `--base-href` и т. п.), задай
`/<имя>/` и регистрируй с `--no-strip`: nginx передаст путь как есть.

## Остановка из панели

У работающего стенда в панели есть кнопка «Остановить», у остановленного — «Удалить».

- «Остановить» показывает список процессов с pid и памятью и после подтверждения
  останавливает их: процесс, который слушает порт стенда, его родительскую обёртку
  (если она есть) и их дочерние процессы. Сначала SIGTERM, через
  15 секунд — SIGKILL. Карточка остаётся в состоянии «остановлен».
- «Удалить» убирает остановленный стенд из прокси (как `bin/envctl rm`). Пока порт стенда
  занят, удаление запрещено.
- Сопутствующие процессы (базы данных, браузеры, сервисы на других портах) не
  останавливаются. Файлы стенда не удаляются.
- nginx, `envctl` и процессы на портах `listen_port` и `control_port` не останавливаются.

Кнопки работают через сервис команд: `bin/envctl api` на `127.0.0.1:<control_port>` (`conf/settings.json`), nginx проксирует к нему `/_env/api/`. Запускается и
останавливается вместе с nginx (`envctl up` / `envctl down`). Лог — `var/logs/api.log`.

Авторизации нет: остановить стенд может любой, кто открыл панель. От случайного клика
защищает подтверждение, от запросов с чужих страниц — обязательный заголовок
`X-Env-Panel: 1`.

API (через nginx, префикс `/_env/api/stands/<имя>/`):

| Запрос | Что делает |
|---|---|
| `GET .../processes` | Процессы, которые будут остановлены |
| `POST .../stop` | Остановить. Нужен заголовок `X-Env-Panel: 1` |
| `POST .../rm` | Удалить остановленный стенд из реестра. Нужен заголовок `X-Env-Panel: 1` |

## Как это устроено

- Запрос `/<имя>/<путь>` уходит на `127.0.0.1:<порт>/<путь>` (префикс срезается).
- Приложение получает заголовки `Host` (внешний), `X-Forwarded-Proto`, `X-Forwarded-Host`,
  `X-Forwarded-Prefix: /<имя>`.
- Редиректы приложения (`Location: /login`, `http://localhost:<порт>/...`) переписываются в
  `/<имя>/...`.
- Путь cookie `Path=/` переписывается в `Path=/<имя>/`, чтобы сессии стендов не смешивались.
- WebSocket проксируется.
- `absolute_redirect off`: nginx не подставляет внутренний `listen_port` в редиректы.
- `/_env/` — служебный путь панели. `/` редиректит на панель. Неизвестный путь — 404.
- Панель берёт список из `/_env/api/stands.json`, состояние — из `/_env/ping/<имя>`
  (HEAD-запрос к стенду; 502 — стенд не отвечает).

## Ограничения

- **Cookie, выставленные из JavaScript с `Path=/`.** nginx переписывает только cookie из ответов
  сервера. Если приложение ставит cookie сессии из JavaScript, два стенда одного приложения в одном
  браузере выбьют друг друга из сессии. Обход: разные стенды — в разных профилях браузера или
  окнах инкогнито.
- **Корневые пути.** Приложение, которое строит ссылки от корня (`/static/...`) и не умеет
  базовый путь, под префиксом работать не будет. Такое приложение подними на порту из `direct_ports`
  напрямую (по указанию пользователя). Переписывание ответов через `sub_filter` в этой схеме не используется.
- **Нет автозапуска.** nginx и сервис команд не зарегистрированы в supervisor. После
  перезапуска контейнера — `bin/envctl up`.

## Диагностика

| Симптом | Что проверить |
|---|---|
| Панель не открывается | `bin/envctl status`; `curl -s localhost:<listen_port>/_env/health` |
| Карточка «остановлен» | Процесс стенда жив? `curl -sI 127.0.0.1:<порт>/` |
| 404 по адресу стенда | Есть ли `stands.d/<имя>.json`; выполнен ли `bin/envctl reload` |
| Редирект на внутренний порт | Приложение отдаёт абсолютный `Location` с чужим хостом; см. `var/logs/access.log` |
| Логи nginx | `var/logs/error.log`, `var/logs/access.log` |
| Кнопки панели: «сервис команд панели недоступен» | `bin/envctl status`; `bin/envctl up`; `var/logs/api.log` |

## Сводка

nginx на `listen_port` (снаружи `$PROXY_URL`) раздаёт стенды под путями `/<имя>/`; панель —
`/_env/`. Стенд поднимается на порту из `bin/envctl free-port` и регистрируется `bin/envctl add`
с `--task <ws>/<задача>`. Реестр — `stands.d/`, остальное генерируется в `var/`. Из панели стенд
можно остановить и удалить; это делает сервис команд на `control_port`, который запускается вместе
с nginx. Порты, диапазон стендов и прямые порты настраиваются в `conf/settings.json`. После
перезапуска машины нужно выполнить `bin/envctl up`.
