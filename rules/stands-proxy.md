# Расширение: стенды, прокси и учётные данные

Это расширение правил из `AGENTS.md` (раздел 6). Оно обязательно так же, как основной документ.

Стенд — любой веб-сервис, который агент поднимает для задачи: приложение, dev-сервер, бэкенд, вспомогательный сервис с веб-интерфейсом. Чтобы стендов могло быть много при ограниченном числе внешних портов, их раздаёт nginx-прокси по путям `/<имя>/`. Код прокси — `$ROOT/infra/nginx-env/`, работающая копия — `$PROXY_DIR` (`env.yaml` → `proxy.dir`).

Расширение **добавляет исключение** к п. 1.1 `AGENTS.md`: агент может создавать, менять и удалять файлы своих стендов в `$PROXY_DIR/stands.d/` и файлы в `$PROXY_DIR/var/` — только через `$PROXY_DIR/bin/envctl`.

---

## 1. Когда применяется

- Раздел `stands` в `ws.yaml` есть и `stands.proxy: true` — стенды регистрируются в прокси по этому документу. Требуется `env.yaml` → `proxy.dir` и `proxy.url`; если они `null` — остановись и сообщи пользователю.
- `stands.proxy: false` — прокси не используется. Порт и способ доступа согласуй с пользователем; разделы 3 и 4 не действуют, разделы 2 и 5 действуют.
- Раздела `stands` нет — стенды в этом пространстве не поднимаются. Если задача требует стенд — спроси пользователя.

## 2. Учётные данные стенда

- Для входа в стенд, его инициализации, E2E-тестов и браузера используй **только** пару из `$SECRETS` по ключам `ws.yaml` → `secrets.stand_login` и `secrets.stand_password`.
- Не придумывай другие логины и пароли и не бери их из кода, примеров и документации (`.env.example`, значения по умолчанию в сценариях и т. п.).
- Если инструмент ждёт другие имена переменных, передай значения через окружение команды, не выводя их:

  ```bash
  export E2E_USER="$(python3 -c 'import yaml,sys; print(yaml.safe_load(open(sys.argv[1]))[sys.argv[2]])' "$SECRETS" STAND_LOGIN)"
  ```

- Значения подчиняются `AGENTS.md`, раздел 5: не выводить, не записывать в файлы, журнал и коммиты.
- Если ключей в `ws.yaml` или `$SECRETS` нет или вход не проходит — **не поднимай стенд с другими данными**. Остановись и сообщи пользователю.

## 3. Порты и регистрация

- Порт стенда — из `$PROXY_DIR/bin/envctl free-port`. Порты из `conf/settings.json` (`listen_port`, `control_port`, `direct_ports`) стендами не занимать; `direct_ports` — только по прямому указанию пользователя.
- Перед запуском проверь, что порт свободен. Если занят — возьми следующий; чужой процесс не останавливай. Один порт — один стенд.
- Сразу после того, как стенд начал отвечать, зарегистрируй его:

  ```bash
  cd "$PROXY_DIR"
  bin/envctl add <имя> --port <порт> --task <ws>/<задача> --session <ID сессии> \
    --kind <тип> --desc "<ветка, что поднято>" [--landing <ws.yaml -> stands.landing>]
  ```

  - `--task` и `--session` обязательны. `--task` — `<ws>/<задача>`, чтобы по карточке было видно пространство.
  - Имя: латиница в нижнем регистре, цифры, `-`. Лучше всего — ключ задачи в нижнем регистре (`pst1-406`). Несколько стендов одной задачи — с суффиксом: `task-406-dev`.
  - `--landing` — из `ws.yaml` → `stands.landing`, если не `null`.
  - Стенд другой сессии не перезаписывай. Если `envctl` отказал из-за чужой сессии — выбери другое имя. `--force` — только с согласия пользователя.
  - Убедись, что nginx запущен (`bin/envctl status`). Если нет — `bin/envctl up`.
- Стенд без регистрации считается не поднятым.

## 4. Проверка и ссылка пользователю

Стенд считается поднятым, только если все проверки прошли:

```bash
bin/envctl status                                                         # стенд «работает»
curl -s -o /dev/null -w '%{http_code}\n' localhost:<listen_port>/<имя><landing>   # 200
curl -sI localhost:<listen_port>/<имя>/ | grep -i location                # если есть: относительный, с /<имя>/
```

Дополнительные проверки для конкретного приложения (вход через браузер, сохранение сессии) описывают правила пространства.

После проверок наступает событие `stand-up` (`AGENTS.md`, п. 8.2). Пользователю даётся ссылка через прокси: `$PROXY_URL/<имя><landing>`. Ссылку `localhost:<порт>` не давай: снаружи она не открывается.

## 5. Остановка

Когда стенд больше не нужен (задача закрыта или пользователь попросил): событие `before-stand-down`, затем останови процесс стенда и выполни `bin/envctl rm <имя>`. Удаляй только свои стенды; чужие — только по просьбе пользователя. `bin/envctl down` выключает доступ ко всем стендам — только по просьбе пользователя.

## 6. Что запрещено

| Действие | Разрешено? |
|---|---|
| Стенд на порту не из `envctl free-port` | Нет (`direct_ports` — только по указанию пользователя) |
| Оставить стенд без регистрации в `envctl` | Нет |
| Править `var/` или чужие файлы в `stands.d/` руками | Нет |
| `bin/envctl down` | Только по просьбе пользователя |
| Править `conf/`, `panel/`, `bin/` | Только если это задача пользователя |
| Останавливать чужие стенды | Нет, спроси пользователя |
| Другой логин или пароль, кроме `stand_login` / `stand_password` | Нет |
| Записать логин, пароль или вывести их в чат | Нет |
| Ссылка пользователю на `localhost:<порт>` | Нет, только `$PROXY_URL/...` |

## 7. Если не работает

- Приложение не открывается под префиксом (белый экран, 404 на `/static/...`, редирект на корень) — оно не умеет работать под базовым путём. Не чини это переписыванием ответов. Сообщи пользователю и предложи порт из `direct_ports`.
- `envctl add` упал с ошибкой `nginx -t` — прежний конфиг восстановлен, другие стенды работают. Покажи ошибку пользователю.
- Логи: `$PROXY_DIR/var/logs/error.log`, `access.log`. Устройство и команды — `$ROOT/infra/nginx-env/README.md`.

## Сводка

Стенд поднимается на порту из `envctl free-port`, сразу регистрируется `envctl add` с `--task <ws>/<задача>` и `--session`, проверяется через прокси и отдаётся пользователю ссылкой `$PROXY_URL/<имя>/...`. Логин и пароль — только из `$SECRETS` по ключам `ws.yaml` → `secrets`, без вывода. По окончании — остановить процесс и `envctl rm`. Чужие стенды, `var/` и nginx целиком не трогать. Где лежит работающий прокси и внешний адрес — `env.yaml` → `proxy`.
