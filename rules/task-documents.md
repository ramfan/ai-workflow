# Расширение: документы задачи

Это расширение правил из `AGENTS.md` (раздел 6). Оно обязательно так же, как основной документ.

---

## 1. Вопросы и план

- Все вопросы по задаче агент пишет только в `$TASK/questions.md`. Это вопросы к человеку, неясности, решения, которые нужно принять.
- В `$TASK/plan.md` — только план: исправления, реализации или исследования. Вопросов в нём нет.
- Если план зависит от ответа на вопрос, в `plan.md` ставится ссылка на вопрос в `questions.md` (например, «см. `questions.md`, вопрос 3»). Сам вопрос в `plan.md` не повторяется.
- Вопросы в `questions.md` нумеруются. Когда человек ответил, ответ записывается под вопросом, вопрос не удаляется.
- Текст обоих файлов — по `rules/human-readable-texts.md`.

### 1.1. Структура `questions.md`

Файл называется только `questions.md` (не `question.md`, не `вопросы.md` и т. п.). Структура у всех задач одинаковая.

```markdown
# Вопросы по <задача> (<кратко, о чём задача или пространство>)

## 1. <Короткий заголовок вопроса>

<Контекст: что известно, откуда (файлы, разделы, ссылки на другие задачи), какие есть варианты.>

<Сам вопрос — одним предложением с вопросительным знаком.>

Ответ: <ответ человека или пусто, пока ответа нет>

## 2. <Следующий вопрос>

...
```

- Заголовок файла — один, уровня `#`: `Вопросы по <задача>` и в скобках уточнение.
- Каждый вопрос — раздел уровня `##` с номером и коротким заголовком: `## <N>. <Заголовок>`. Номера идут подряд с 1, не переиспользуются и не меняются.
- Внутри вопроса в таком порядке: абзац контекста, отдельный абзац с самим вопросом, строка `Ответ:`.
- Строка с ответом есть у каждого вопроса, без исключений. Новый вопрос, на который ещё не ответили, агент записывает сразу со строкой `Ответ: ` (двоеточие и пробел, дальше пусто). Человек дописывает ответ в эту строку.
- Уточнения, полученные позже (например, в чате), дописываются после строки `Ответ:` отдельным абзацем: `Уточнение в чате (<ГГГГ-ММ-ДД>): <текст>.`
- Новые вопросы добавляются в конец файла.

## 2. Контекст задачи `.context.md`

Файл `$TASK/.context.md` — краткая рабочая память по задаче: что нужно сделать, на чём остановились, какой вариант выбран, какие проблемы и разногласия, где что лежит. Ведёт его агент; человек читает, но не редактирует.

- **Читать обязательно.** Перед началом работы над задачей агент читает `.context.md`, если он есть (`AGENTS.md`, раздел 3). Это точка входа в задачу: дальше он идёт по ссылкам из контекста и по `issue`.
- **Когда обновлять.** При первом запуске задачи, после исследования, плана, этапа реализации, смены решения, появления проблемы или разногласия. Хук — `hook:context-task`.
- **Не раздувать.** Числового предела нет, но объём растёт только по необходимости: самое важное и нужное. Устаревшее заменяется или удаляется, а не дописывается рядом.
- **Не дублировать.** Описание задачи, полный план, вопросы и журнал остаются в своих файлах. В `.context.md` — одна строка сути и ссылка.
- **Секреты.** Не вставлять секреты и значения из `$SECRETS`; можно только имя ключа.
- **Источник правды.** `task.yaml` и `issue` важнее `.context.md`. Если они расходятся — верь им и обнови `.context.md`.

### 2.1. Структура `.context.md`

```markdown
# Контекст задачи <задача>

- Обновлён: <ГГГГ-ММ-ДД ЧЧ:ММ>
- Пространство: <ws>
- Стадия: <task.yaml -> stage>
- Ветка: <git.branch или «нет»>; worktree: <путь или «нет»>

## Цель
<1–3 предложения: что должно получиться.>

## Где остановились
<последнее сделанное, что проверено, что запущено; ссылки на journal/.>

## Выбранный вариант и решения
<какой вариант выбран и почему; отклонённые варианты — одной строкой; ключевые решения.>

## Проблемы и разногласия
<что мешает; с чем не согласны агент и человек; что требует решения.>

## Ссылки
- Задача: <Jira/трекер или «нет»>
- MR: <ссылки или «нет»>
- Стенд: <ссылка или «нет»>
- Документы: <plan.md, questions.md, journal/ и другие файлы задачи>
- Код и внешние материалы: <ссылки/пути>

## Следующий шаг
<одно конкретное действие.>
```

- Разделы структуры не удаляй. Если сведений нет — `нет` или одна строка, почему пусто.
- Если файла ещё нет (первый запуск), создай каркас сразу: цель, стадия, ветка, ссылки, известные ограничения и первый шаг. Решения, проблемы и разногласия дополняются по ходу работы.

## 3. Краткая памятка

| Действие | Разрешено? |
|---|---|
| Вопросы по задаче в `questions.md` | Да |
| Вопросы в `plan.md` | Нет, только ссылка на вопрос в `questions.md` |
| В `plan.md` что-либо, кроме плана | Нет |
| Удалить вопрос из `questions.md` после ответа | Нет, ответ записывается под вопросом |
| Файл вопросов с другим именем (`question.md` и т. п.) | Нет, только `questions.md` |
| `questions.md` в своей структуре | Нет, только по разделу 1.1 |
| Перенумеровать вопросы | Нет |
| Вопрос без строки `Ответ: ` | Нет, у нового вопроса строка `Ответ: ` пустая |
| Начать работу, не прочитав `.context.md`, когда файл есть | Нет |
| Обновить `.context.md` после этапа работы | Да |
| Дописывать в `.context.md` новую версию вместо замены устаревшей | Нет |
| Дублировать в `.context.md` описание, план, вопросы, журнал | Нет, только ссылка и суть |
| Секреты и их значения в `.context.md` | Нет, только имя ключа |
| Числовой предел объёма `.context.md` | Нет, но растёт только по необходимости |

## Сводка

Документы задачи делятся на три части. `questions.md` — только вопросы к человеку, с ответами под ними. `plan.md` — только план, без вопросов. `.context.md` — краткая рабочая память: цель, где остановились, выбранный вариант, проблемы и разногласия, ссылки, следующий шаг. Контекст читается перед работой обязательно, обновляется по ходу и не раздувается: подробности остаются в описании задачи, плане, вопросах и журнале, а здесь — суть и ссылка. Секреты в документы не попадают.
