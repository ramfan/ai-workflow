# Расширение: настройки в YAML

Это расширение правил из `AGENTS.md` (раздел 6). Оно обязательно так же, как основной документ.

Все настройки окружения, пространств и задач хранятся в YAML по строгим схемам. Агент читает их, проверяет по схеме и только потом работает. Правила, учёт и журналы остаются в Markdown.

---

## 1. Общие правила

- Файлы: `$ROOT/env.yaml`, `$SECRETS`, `workspaces/<ws>/ws.yaml`, `workspaces/<ws>/tasks/<задача>/task.yaml`. Шаблоны с комментариями к каждому полю — в `$ROOT/templates/`.
- Схема строгая:
  - обязательное поле отсутствует — ошибка;
  - поле, которого нет в схеме, — ошибка;
  - неверный тип или значение вне списка допустимых — ошибка;
  - заглушка из шаблона (`path/to/...`, `template`, пустая строка там, где нужно значение) — ошибка.
- При ошибке **СТРОГО ЗАПРЕЩАЕТСЯ** продолжать. Остановись и сообщи пользователю: файл, поле, что не так. Значение не додумывай.
- Файлы настроек заполняет человек. Агент меняет их только по прямой просьбе пользователя.
- Проверка: `$ROOT/bin/check-config [<ws>]` (Python 3 + PyYAML) проверяет все файлы по схемам ниже и печатает ошибки. Если скрипт недоступен — сверь поля со схемой вручную.

### 1.1. Подстановка переменных

В строковых значениях `env.yaml` и `ws.yaml` допускаются подстановки `${ИМЯ}`:

| Подстановка | Значение |
|---|---|
| `${ROOT}` | `$ROOT` — папка, где лежит `AGENTS.md` |
| `${TMP_DIR}` | `env.yaml` → `tmp_dir` |
| `${SECRETS_FILE}` | `env.yaml` → `secrets_file` |
| `${PROXY_DIR}`, `${PROXY_URL}` | `env.yaml` → `proxy.dir`, `proxy.url` |
| `${ИМЯ}` | `env.yaml` → `vars.ИМЯ` |

- Подстановка раскрывается при чтении. Неизвестное имя — ошибка.
- В `task.yaml` подстановки не используются.
- Относительные пути в `ws.yaml` → `rules` считаются от папки пространства; в `task.yaml` → `issue` — от папки задачи. Остальные пути — абсолютные или через подстановки.

## 2. `env.yaml`

Переменные этой копии `ai-workflow`. Лежит в `$ROOT/env.yaml`, не коммитится. Шаблон — `templates/env.yaml`.

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `tmp_dir` | строка, путь | да | Папка для временных файлов агента. Должна существовать или создаваться агентом. |
| `secrets_file` | строка, путь | да | Файл секретов (раздел 5). |
| `proxy` | словарь | да | Прокси стендов. |
| `proxy.dir` | строка, путь или `null` | да | Папка с `bin/envctl`. `null` — стенды через прокси не используются. |
| `proxy.url` | строка или `null` | да | Внешний адрес прокси: схема, хост, порт. `null` вместе с `proxy.dir: null`. |
| `vars` | словарь «ИМЯ → строка» | да (может быть пустым `{}`) | Свои переменные. Имя: `[A-Z][A-Z0-9_]*`. |

---

## 3. `ws.yaml`

Настройки пространства. Лежит в `workspaces/<ws>/ws.yaml`. Шаблон — `templates/ws.yaml`.

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `name` | строка | да | Имя пространства. Равно имени папки `<ws>`. Латиница в нижнем регистре, цифры, `-`. |
| `description` | строка | да | Что это за проект. |
| `sources` | список, не пустой | да | Где лежит код. |
| `sources[].path` | строка, путь | да | Папка. Должна существовать. |
| `sources[].kind` | `repo` \| `repos-dir` | да | `repo` — `path` сам git-репозиторий. `repos-dir` — внутри `path` лежат git-репозитории на любой глубине; каждый — отдельный репозиторий, все с `access` источника. |
| `sources[].access` | `write` \| `ask` \| `read` | да | Права на правки (`AGENTS.md`, раздел 1). |
| `git` | словарь | да | Настройки git по умолчанию. |
| `git.submodules` | булево | да | Есть ли подмодули, которые нужно скачивать в worktree. |
| `git.root_branch` | булево | да | Создавать ли ветку задачи в корневом репозитории. `false` — корень без ветки (detached), правки только в подмодулях. Имеет смысл при `submodules: true`. |
| `git.jira_in_commit` | булево | да | Писать ли ключ `task.yaml` → `jira` в сообщениях коммитов. |
| `rules` | список строк | да (может быть `[]`) | Правила пространства — пути к Markdown-файлам относительно папки пространства. Каждый файл должен существовать. |
| `secrets` | словарь «сервис → ключ» | да (может быть `{}`) | Какой ключ из `$SECRETS` брать для сервиса. Ключ должен быть в `$SECRETS`. Сервисы `jira`, `gitlab`, `stand_login`, `stand_password` понимают общие правила; остальные описываются в правилах пространства. |
| `stands` | словарь | нет | Стенды. Нет раздела — стенды не поднимаются. |
| `stands.proxy` | булево | да, если есть `stands` | Регистрировать стенды в прокси (`rules/stands-proxy.md`). `true` требует `env.yaml` → `proxy.dir`. |
| `stands.landing` | строка или `null` | да, если есть `stands` | Путь после префикса стенда, который открывает пользователь. |

Папка `workspaces/<ws>/` содержит только: `ws.yaml`, `rules/`, `tasks/`, `_archive/`. Другие папки в корне пространства не создаются.

## 4. `task.yaml`

Настройки задачи. Лежит в `workspaces/<ws>/tasks/<задача>/task.yaml`. Шаблон — `templates/task.yaml`. Заполняет человек; агент не меняет.

| Поле | Тип | Обязательно | Что это |
|---|---|---|---|
| `issue` | строка, путь относительно папки задачи | да | Файл с описанием задачи. Должен существовать. |
| `jira` | строка или `null` | да | Ключ задачи в трекере. Нужен в коммитах, если `ws.yaml` → `git.jira_in_commit: true`. |
| `stage` | `research` \| `plan` \| `implement` | да | Стадия (раздел 4.1). |
| `journal` | булево | да | Вести журнал (`rules/journal.md`). |
| `git` | словарь | да | |
| `git.base_branch` | строка | да | От какой ветки создаётся ветка задачи. В `research`/`plan` — какую ветку исследовать, если `branch` пуст. |
| `git.branch` | строка или `null` | да | Ветка задачи. Для `implement` обязательна (не `null`). Одно имя во всех репозиториях и подмодулях. |
| `git.root_branch` | булево или `null` | да | Переопределение `ws.yaml` → `git.root_branch`. `null` — взять из пространства. |
| `git.commit` | `true` \| `ask` \| `false` | да | Коммиты: разрешены / спрашивать перед каждым / запрещены. |
| `git.push` | `true` \| `ask` \| `false` | да | Push и создание MR: разрешены / спрашивать перед каждым / запрещены. |
| `git.merge_request_title` | строка или `null` | да | Заголовок MR, одинаковый во всех репозиториях задачи. `null` — MR не создаётся. |

### 4.1. Стадии

| `stage` | Что делает агент | Worktree | Коммиты, push |
|---|---|---|---|
| `research` | Исследует код, воспроизводит проблему, пишет документы в `$TASK/` (например, `research.md`, `questions.md`). Код не правит. | Без ветки, только чтение | Запрещены независимо от `git.commit` / `git.push` |
| `plan` | То же, что `research`, плюс план реализации в `$TASK/` (например, `plan.md`). Код не правит. | Без ветки, только чтение | Запрещены |
| `implement` | Правит код по описанию и плану, если он есть. | На ветке `git.branch` | По `git.commit` / `git.push` |

Стадию меняет только пользователь в `task.yaml`. Если по итогам `research` или `plan` нужны правки — сообщи пользователю и остановись.

Соответствие старым Markdown-задачам: «исследование» → `research`, «исследование + план» → `plan`, «исправление», «реализация» → `implement`; «разрешены» → `true`, «только по согласованию» → `ask`, «запрещён» → `false`.

---

## 5. `$SECRETS`

Файл секретов из `env.yaml` → `secrets_file`. Шаблон — `templates/secrets.yaml`.

- Плоский словарь «ключ → строка». Ключ: `[A-Z][A-Z0-9_]*`. Вложенные структуры запрещены.
- Агент читает только ключи, перечисленные в `ws.yaml` → `secrets`. Остальное содержимое файла не выводит и не анализирует.
- Обращение со значениями — `AGENTS.md`, раздел 5.

---

## 6. Краткая памятка

| Действие | Разрешено? |
|---|---|
| Работать при отсутствующем или неверном `env.yaml` | Нет, попроси создать по `templates/env.yaml` |
| Продолжать при ошибке схемы в `ws.yaml` или `task.yaml` | Нет, остановись и сообщи поле |
| Додумать значение пропущенного поля | Нет |
| Поле вне схемы | Ошибка, сообщи |
| Менять `env.yaml`, `ws.yaml`, `task.yaml`, `$SECRETS` без просьбы | Нет |
| Коммит или push в стадии `research` / `plan` | Нет |
| `implement` без `git.branch` | Нет, спроси |
| Подстановка `${ИМЯ}`, которой нет в `env.yaml` | Ошибка, сообщи |

## Сводка

Четыре YAML-файла: `env.yaml` (пути машины, прокси, свои переменные), `$SECRETS` (плоский словарь ключей), `ws.yaml` (источники кода с `access`, настройки git, правила и секреты пространства, стенды), `task.yaml` (описание, стадия, ветки, права на коммит и push, заголовок MR). Схемы строгие: лишнее, пропущенное или неверное поле — остановка и вопрос пользователю. Стадии `research` и `plan` — только чтение и документы; `implement` — правки на ветке задачи.
