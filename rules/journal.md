# Расширение: журнал выполнения задачи

Это расширение правил из `AGENTS.md` (раздел 6). Оно обязательно так же, как основной документ.

Журнал ведёт агент, человек его не редактирует. Журнал ведётся, только если в `task.yaml` `journal: true`.

---

## 1. Где лежит

- Папка `$TASK/journal/`. Агент создаёт её при первом этапе.
- Каждый этап — отдельный файл `journal/<NN>-<краткое-название>.md`. `NN` — порядковый номер с ведущим нулём: `01`, `02`, … Название — латиница в нижнем регистре, цифры, `-`.
- Оглавление — `journal/README.md`: нумерованный список ссылок на этапы по порядку. Агент дополняет его после создания каждого файла этапа.

## 2. Когда писать этап

Новый этап — при каждом логически завершённом шаге: исследование, план, реализация части, стенд, ревью, MR, закрытие. Также в конце сессии, если работа не закончена: кратко, что сделано и что осталось.

Файл этапа не переписывается задним числом. Уточнения — новым этапом.

## 3. Структура файла этапа

```markdown
# <NN>. <Название этапа>

- Дата: <date '+%Y-%m-%d %H:%M %z'>
- Стадия: <task.yaml -> stage>
- Ветка / коммиты: <ветка, SHA коммитов этапа, если были; иначе «нет»>

## Цель этапа

## Что сделано

## Результат
(факты, выводы, затронутые файлы, найденные проблемы)

## Открытые вопросы
(что требует решения человека; если нет — «нет»)

## Следующий шаг
```

## 4. Требования

- Текст — по `rules/human-readable-texts.md`.
- Секреты, логины, пароли в журнал не пишутся (`AGENTS.md`, раздел 5).
- Остальные документы задачи (планы, исследования, вопросы, отчёты) лежат в `$TASK/` рядом с описанием, а не в `journal/`. Журнал на них ссылается.

## 5. Краткая памятка

| Действие | Разрешено? |
|---|---|
| Журнал при `journal: false` | Нет |
| Переписать старый этап | Нет, новый этап |
| Этап без записи в `journal/README.md` | Нет |
| Секреты в журнале | Нет |
