# Расширение: оформление Merge Request

Это расширение правил из `AGENTS.md` (раздел 6). Оно обязательно так же, как основной документ.

Правила ниже действуют для любого MR по задаче: в каждом репозитории и подмодуле, который затронула задача. Термины — из `rules/worktrees.md` (раздел 1).

---

## 1. Поле в `task.yaml`

| Поле | Что это |
|---|---|
| `git.merge_request_title` | Заголовок MR. `null` — MR не создаётся. |

Если MR нужно создать, а поле `null`, пустое или в нём заглушка — **не создавай MR**. Остановись и спроси пользователя.

---

## 2. Заголовок

- Заголовок каждого MR по задаче — **точно** значение `git.merge_request_title`, без изменений и дополнений.
- Заголовок одинаковый во всех репозиториях и подмодулях задачи. По нему пользователь находит все MR задачи.

---

## 3. Когда можно создавать MR

Создание MR — это отправка на сервер. Оно подчиняется `task.yaml` → `git.push`:

| `push` | Что делать |
|---|---|
| `true` | Создавай MR сам. |
| `ask` | Перед созданием каждого MR спроси пользователя. |
| `false` | MR не создавай. |

Перед созданием MR наступает событие `before-push` (`AGENTS.md`, п. 8.2).

---

## 4. Описание MR

- Текст — по `rules/human-readable-texts.md`.
- Если задача затронула несколько репозиториев, в описании каждого MR укажи ссылки на остальные MR задачи и порядок слияния, если он важен.
- Токен для API берётся из `ws.yaml` → `secrets.gitlab` (`AGENTS.md`, раздел 5).

---

## 5. Краткая памятка

| Действие | Разрешено? |
|---|---|
| MR с заголовком, отличным от `git.merge_request_title` | Нет |
| Создать MR при `merge_request_title: null` | Нет, спроси пользователя |
| Создать MR при `push: false` | Нет |
| Создать MR при `push: ask` без вопроса | Нет |
