# Хук: check-leaks

**Назначение:** проверить, что в git `$ROOT` не попадает конкретика пространств и машины: имена проектов, задач, репозиториев, хосты, локальные пути, значения секретов. Ничего не меняет.

## Аргументы

| Аргумент | Обязательный | Что это |
|---|---|---|
| `history` | нет | Проверить ещё всю историю git: все ветки, сообщения коммитов, изменённые строки. Без него — только то, что попадёт в коммит. |

## Что нужно до запуска

- Есть `$ROOT/env.yaml`. Нет — термины машины и источников не собрать: сообщи и проверяй только пространства и задачи.

## Шаги

Хук только читает файлы. Значения секретов не выводит — только имена ключей.

1. **Скрипт.** Запусти `$ROOT/bin/check-leaks` (с `--history`, если передан `history`) и покажи вывод. Скрипт собирает термины из того, что не коммитится: имена пространств и задач, ключи задач (`ABC` из `ABC-123`), источники из `ws.yaml`, имена репозиториев внутри них, хосты и пути их `remote`, свои переменные и пути из `env.yaml`, значения из `$SECRETS`. Затем ищет эти термины в файлах, которые попадут в коммит (`git ls-files -co --exclude-standard`). Если скрипт не запускается (нет Python 3 или PyYAML) — собери термины и поищи их вручную по тому же списку.
2. **Ложные находки.** Если термин — обычное слово, которое случайно совпало с именем репозитория или папки (например, модуль назван так же, как стандартная функция языка), отметь находку как ложную и перезапусти скрипт с `--allow <слово>`. Если сомневаешься — считай находку настоящей.
3. **Ручной просмотр изменений.** Прочитай незакоммиченные изменения: `git diff HEAD` и новые неигнорируемые файлы (`git ls-files -o --exclude-standard`). Ищи конкретику, которую скрипт не ловит по словам:
   - названия продуктов, компаний, внутренних сервисов и утилит конкретного проекта;
   - технологии и детали устройства конкретного проекта (базы, версии, пути внутри его сборки, базовые URL вроде `/<путь>/`), поданные как общее правило;
   - примеры с настоящими ключами задач, именами веток, людей, адресами, портами;
   - ссылки на файлы внутри `workspaces/<ws>/` конкретного пространства.

   Общие правила должны описывать механизм, а конкретика пространства — лежать в `workspaces/<ws>/rules/` (они не коммитятся). Найденное не по словарю перепроверь скриптом с `--term <слово>`.

## Результат

- Таблица находок: файл и строка (для истории — коммит и файл), термин или вид конкретики, откуда термин (пространство, репозиторий, `env.yaml`, секрет — только имя ключа), настоящая или ложная.
- Для каждой настоящей находки — предложение: что заменить на общую формулировку и что перенести в правила пространства. Правки — только по просьбе пользователя.
- Если находки есть в истории git — сообщи, что убрать их можно только переписав историю, и ничего не делай без прямой просьбы.
- Если находок нет — так и скажи.

## Сводка

`hook:check-leaks [history]` запускает `bin/check-leaks`: тот собирает термины из локальных, не коммитящихся данных (пространства, задачи, репозитории и их `remote`, `env.yaml`, секреты) и ищет их в том, что попадёт в git, а с `history` — и во всей истории. Затем агент вручную просматривает незакоммиченные изменения в поисках конкретики, которую не поймать по словам. Хук ничего не меняет и только предлагает исправления.
