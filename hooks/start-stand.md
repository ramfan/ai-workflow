# Хук: start-stand

**Назначение:** поднять стенд задачи по правилу стенда пространства, зарегистрировать его в прокси и выдать пользователю ссылку.

## Аргументы

| Аргумент | Обязательный | Что это |
|---|---|---|
| `<ws>/<задача>` | да | Задача, для которой поднимается стенд. |
| `[параметры]` | нет | Параметры стенда. Их состав, порядок и значения по умолчанию задаёт правило стенда пространства. |

Имя стенда в прокси — по правилу стенда. Если правило его не задаёт — имя задачи в нижнем регистре.

## Что нужно до запуска

- Задача в `workspaces/<ws>/tasks/<задача>/` с `task.yaml`, подготовка по `AGENTS.md`, раздел 3, выполнена.
- В `ws.yaml` есть раздел `stands`.
- В `ws.yaml` → `rules` подключено правило стенда — файл с разделом «Запуск через `hook:start-stand`». В нём перечислены параметры хука и разделы правила для каждого шага ниже. Нет такого правила — остановись и сообщи: как поднимать стенд в этом пространстве, не описано.
- Прочитаны `rules/stands-proxy.md` и правило стенда целиком.

## Шаги

Каждый шаг выполняется по разделам правила стенда, которые указаны для него в разделе «Запуск через `hook:start-stand`». Если правило задаёт другой порядок или дополнительные шаги — следуй правилу.

1. **Проверка.** Нет ли уже стенда задачи: `bin/envctl status` из `$PROXY_DIR`, журнал задачи. Если есть — сообщи ссылку и остановись. Определи параметры стенда, рабочую папку, порт и имя. Если параметр неоднозначен — спроси.
2. **Секреты.** Проверь, что в `ws.yaml` → `secrets` есть все сервисы, нужные правилу стенда, а их ключи есть в `$SECRETS`. Значения не выводи. Нет ключа — остановись и сообщи его имя.
3. **Сборка и запуск.** Разделы правила стенда, указанные для этого шага, по порядку.
4. **Регистрация и проверка.** `rules/stands-proxy.md`, разделы 3–4, и проверки из правила стенда.
5. **Событие `stand-up`.** Проверь `hooks/TRIGGERS.md` и запусти привязанные хуки (`AGENTS.md`, п. 8.2), `{stand}` = имя стенда.
6. **Журнал.** По `rules/journal.md`, если в `task.yaml` `journal: true`.

Если шаг упал и правило не описывает обход — остановись, покажи ошибку и последние строки лога. Не продолжай и не подбирай обход сам.

## Результат

Сообщи пользователю:

- ссылку `$PROXY_URL/<имя>/` с `ws.yaml` → `stands.landing`;
- что ещё перечислено в результате раздела «Запуск через `hook:start-stand`» правила стенда;
- результаты проверок (`envctl status` и проверки из правила);
- как остановить: `hook:stop-stand <имя>` и раздел правила стенда об остановке.

## Сводка

`hook:start-stand <ws>/<задача> [параметры]` поднимает стенд по правилу стенда пространства — файлу из `ws.yaml` → `rules` с разделом «Запуск через `hook:start-stand`». Хук проверяет, нет ли уже стенда задачи, и проверяет секреты. Затем собирает и запускает стенд по разделам правила, регистрирует его в прокси, проверяет и выдаёт ссылку. Если стенд задачи уже работает — только сообщает ссылку. Если в пространстве нет правила стенда — останавливается.
