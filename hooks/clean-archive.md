# Хук: clean-archive

**Назначение:** удалить worktree и остановить стенды задач, которые уже лежат в `workspaces/<ws>/_archive/`.

## Аргументы

| Аргумент | Обязательный | Что это |
|---|---|---|
| `<ws>` | нет | Имя пространства. Без него — все пространства. |
| `<задача>` | нет | Имя папки задачи в `workspaces/<ws>/_archive/`. Без него — все архивные задачи пространства, у которых есть worktree. Требует `<ws>`. |

## Что нужно до запуска

- Задача уже перенесена в `_archive/` (`AGENTS.md`, п. 2.7). Задачи из `tasks/` хук не трогает.
- Прочитаны `rules/worktrees.md` (разделы 7 и 8) и `rules/stands-proxy.md`.

## Шаги

Вызов хука — прямая просьба пользователя:
- закрыть обрабатываемые архивные задачи и удалить их worktree (`rules/worktrees.md`, раздел 7);
- остановить их стенды и удалить их из прокси;
- поменять их строки в `registry/WORKTREES.md`, даже если строки создала другая сессия.

Файлы задачи, `journal/` и другие файлы в папке задачи, кроме worktree, хук не трогает. Worktree задач из `tasks/` не трогает.

1. **Список задач.**
   - Если указано `<ws>` — проверь, что `workspaces/<ws>/ws.yaml` есть. Если указана `<задача>` — проверь имя (латиница, цифры, `-`, `_`, без `..` и пробелов) и что папка `workspaces/<ws>/_archive/<задача>/` есть. Если нет — остановись и сообщи. Если такая папка есть и в `tasks/` — остановись и спроси.
   - Собери worktree задачи из двух источников:
     - строки `registry/WORKTREES.md`, у которых «Путь worktree» начинается с `workspaces/<ws>/_archive/<задача>/`;
     - `git worktree list --porcelain` в основных копиях репозиториев, упомянутых в этих строках: worktree, путь которых лежит внутри `workspaces/<ws>/_archive/<задача>/`.
   - Без аргументов — то же для всех папок во всех `workspaces/*/_archive/`.
   - Если у задачи нет ни одного worktree — пропусти её с причиной «worktree нет».
   - Покажи пользователю найденный список (пространство, задача, репозиторий, путь worktree, стенды) и продолжай.

2. **Расхождения учёта.** Для каждого worktree:
   - есть в git, нет в учёте — обрабатывай дальше, в отчёте отметь «не было в учёте»;
   - есть в учёте, нет в git — не удаляй ничего с диска, только удали строку на шаге 7 и отметь «осиротевшая строка»;
   - путь в git не совпадает с путём в учёте — пропусти worktree с причиной «пути не совпадают».

3. **Проверка на неотправленные изменения** (`rules/worktrees.md`, раздел 7, шаг 1). В каждом worktree:

   ```bash
   cd <путь-worktree>
   git status --short
   git log --oneline HEAD --not --remotes
   git submodule foreach --recursive 'git status --short; git log --oneline HEAD --not --remotes'
   ```

   Если вывод не пустой — **не удаляй** этот worktree и не трогай его стенды. Запомни, что именно не отправлено (файлы, SHA коммитов, подмодуль), и переходи к следующему. В учёте поставь в «Комментарий» «clean-archive: пропущен, есть неотправленные изменения», статус не меняй.

4. **Проверка, что в worktree никто не работает.**
   - Процессы с рабочей папкой или аргументами внутри worktree: `ls -l /proc/*/cwd 2>/dev/null | grep <путь-worktree>`, `pgrep -af <путь-worktree>`.
   - Если процесс — стенд этой задачи (шаг 5), его остановят на шаге 5.
   - Если это сессия агента, сборка или процесс, принадлежность которого непонятна, — пропусти worktree с причиной «в worktree работает процесс <pid, команда>».

5. **Стенды задачи.** Только для worktree, прошедших шаги 3 и 4. Все команды envctl — из `$PROXY_DIR`. Если `proxy.dir` в `env.yaml` `null` — этот шаг пропускается, в отчёте «прокси не настроен».
   - Найди стенды:
     - `bin/envctl status` и `stands.d/*.json`: записи, у которых `task` — `<ws>/<задача>` или начинается с него;
     - комментарий строки учёта и журнал задачи: незарегистрированные стенды, порты, контейнеры, браузеры с отладочным портом;
     - процессы из шага 4.
   - Перед остановкой покажи пользователю, что будет остановлено (имя, порт, pid, команда), и продолжай.
   - Останови каждый процесс стенда: найди pid по порту (`ss -ltnp 'sport = :<порт>'`) или из шага 4, `kill <pid>`, через 10 секунд проверь, что порт свободен. Если процесс не остановился — `kill -9 <pid>` и снова проверь.
   - Контейнеры останавливай тем же способом, каким их поднимали (по журналу задачи). Если способ не указан — пропусти контейнер и сообщи.
   - Зарегистрированный стенд удали из прокси: `bin/envctl rm <имя>`. Затем `bin/envctl status`: записи нет.
   - Порты из `direct_ports` и чужие стенды: останавливай, только если по учёту или журналу точно видно, что стенд этой задачи. Если есть сомнение — не трогай, сообщи.
   - Не запускай `bin/envctl down`.
   - Если стенд не удалось остановить — не удаляй worktree, пропусти его с причиной.

6. **Удаление worktree** (`rules/worktrees.md`, раздел 7, шаг 2). Поставь в учёте статус `удаляется`. В основной копии репозитория:

   ```bash
   git worktree unlock <путь-worktree>
   git worktree remove --force <путь-worktree>
   git worktree prune
   ```

   - Ошибку `is not locked` у `unlock` пропусти, остальные ошибки — остановка обработки этого worktree, в учёте статус `ждёт ответа`, в отчёт.
   - Для репозиториев из источников с `access: ask` или `read` команды меняют метаданные git в основной копии. Выполняй их, только если пользователь при вызове хука явно разрешил удалять worktree этих источников. Иначе пропусти с причиной «нужно разрешение на источник <path>».

7. **Учёт** (`rules/worktrees.md`, раздел 7, шаг 3).
   - Проверь, что worktree нет в `git worktree list` и папки на диске нет.
   - Удали строку worktree из `registry/WORKTREES.md` точечно (инструмент Edit). Строки других задач не трогай, файл целиком не перезаписывай.

## Результат

Сообщи пользователю таблицей по каждому найденному worktree:

| Пространство | Задача | Путь worktree | Итог | Стенды | Причина / что не отправлено |
|---|---|---|---|---|---|

- «Итог»: `удалён`, `пропущен`, `ошибка`.
- «Стенды»: что остановлено и удалено из прокси, что осталось.
- Для пропущенных из-за неотправленных изменений — список файлов и SHA коммитов, чтобы пользователь решил, отправить их или удалить вручную.
- Отдельно — осиротевшие строки учёта и worktree, которых не было в учёте.

## Сводка

Хук чистит архивные задачи: одну, все в пространстве или все вообще. Для каждого worktree проверяет неотправленные изменения и работающие процессы; если они есть — пропускает worktree и сообщает. Иначе останавливает стенды задачи, удаляет их из прокси (`envctl rm`), удаляет worktree через `git worktree remove --force` и строку из `WORKTREES.md`. Файлы задачи и журнал не трогает. Worktree источников с `access: ask` / `read` удаляет только с явного разрешения при вызове. В конце — таблица с итогом по каждому worktree.
