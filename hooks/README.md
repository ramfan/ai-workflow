# Хуки

Хук — это именованная инструкция для агента. Агент читает файл хука и выполняет описанные в нём шаги.

Правила запуска — `AGENTS.md`, раздел 8.

## Как запускается

- **Вручную** — в чате:
  ```
  hook:<имя-хука> [аргументы]
  ```
  Например: `hook:new-task project-frontend TASK-123`.
- **Автоматически** — при событии, если хук привязан к нему в `TRIGGERS.md`. Агент не спрашивает подтверждения, но сообщает о запуске и результате.

## Как устроен хук

- Один хук — один файл `hooks/<имя-хука>.md`. Имя файла без `.md` — это имя хука.
- Имя: латиница в нижнем регистре, цифры, `-`.
- `README.md` и `TRIGGERS.md` — не хуки.
- Новый хук создаётся по шаблону `templates/hook.md`.
- Чтобы хук запускался автоматически, добавь строку в `TRIGGERS.md`.

## Список хуков

| Имя | Что делает | События (из `TRIGGERS.md`) |
|---|---|---|
| `new-workspace` | Создаёт пространство `workspaces/<ws>/` с `ws.yaml` из шаблона, папками `rules/`, `tasks/`, `_archive/`. Аргумент — имя пространства | — |
| `new-task` | Создаёт папку задачи `workspaces/<ws>/tasks/<задача>/` с `task.yaml` и `task.md` из шаблонов. Аргументы — пространство и имя задачи | — |
| `check-config` | Проверяет `env.yaml`, `$SECRETS`, `ws.yaml` всех пространств и `task.yaml` всех задач по схемам из `rules/config.md`. Ничего не меняет. Аргумент (необязательный) — пространство | — |
| `clean-archive` | Для задач из `_archive/` останавливает стенды, удаляет их из прокси, удаляет worktree и строки учёта. Worktree с неотправленными изменениями пропускает. Аргументы (необязательные) — пространство и задача | — |
| `stop-stand` | Останавливает процесс на порту стенда и удаляет стенд из прокси (`envctl rm`). Сопутствующие процессы только перечисляет. Аргумент — имя стенда | — |
